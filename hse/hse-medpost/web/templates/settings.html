What it is

Every regency and city with its province and what the Kemenkes malaria map says about it. Other databases read it instead of copying names, so a name they store always matches the one shown here. Read-only.

Address
  • https://medical-activities.ayahaif.my.id/api/directory/regions
Access

Send Authorization: Bearer <token>. Either token from the Employee API page works. The regency list is not sensitive, so give other databases the eligible token.

Freshness

The names follow the Region list on the Region & malaria data page, and the endemicity follows its applied list. After a refresh or an Apply, the new content is served at once.

One regency
{
  "code": "62.12",
  "name": "Kabupaten Murung Raya",
  "province": "Kalimantan Tengah",
  "endemicity": {
    "status": "low",
    "label": "Endemis Rendah",
    "free": false,
    "dataYear": 2026,
    "per1000": 2.39,
    "appliedAt": "2026-11-14"
  }
}

The response is a list of these, ordered by province and then name. The values above are an example.

Fields
FieldMeaning
code name provinceThe regency's code (for example 62.12), official name and province name.
endemicity.statusfree (the map's Eliminasi), low (Endemis Rendah), medium (Endemis Sedang), high (Endemis Tinggi I, II or III), or unknown.
endemicity.labelThe map's own wording, including Tinggi I / II / III.
endemicity.freeTrue only for Eliminasi.
endemicity.dataYearThe map year the row comes from. An older year for regencies the newest map does not have yet.
endemicity.per1000Cases per 1,000 of the total population, as the map computes it. It can disagree with the label.
endemicity.appliedAtThe date the endemicity list was applied.

unknown means there is no data for that regency. It must never be read as free. It is also what every regency says until an admin has read the map and applied it. The map's case data is not yet validated by Kemenkes.

Eligible token

For a database that may only receive Fit and Fit with note checkups that are still valid. This token cannot open the full checkup list.

  • https://medical-activities.ayahaif.my.id/api/directory/fitness
  • https://medical-activities.ayahaif.my.id/api/directory/employees
All checkups token

For a database that may receive every checkup, including unfit, overdue, and archived. This token can also read the eligible list.

  • https://medical-activities.ayahaif.my.id/api/directory/checkups
  • https://medical-activities.ayahaif.my.id/api/directory/latest-checkups

checkups: every checkup of every employee, with the exam sections. latest-checkups: one row per employee with their latest checkup, whatever the result (Unfit, Incomplete, overdue and archived included), without exam sections or ID numbers.

Both accept these optional filters, so a database does not have to download everything: patientId, employeeId, q (part of the name), result (Fit, Fit with note, Unfit, Temporarily Unfit, Need follow up, Incomplete), from and to (yyyy-MM-dd, on the checkup date). checkups also accepts checkUpId. On latest-checkups the filters apply to each employee's latest checkup. Send Authorization: Bearer <all-checkups token>.
