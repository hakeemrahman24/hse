# web

Server-rendered HTML (Go `html/template`) + static JS/CSS for `hse-medpost`.

## Templates/UI

`login.html`, `settings.html`, `programs.html`, and the `clearwave` design system in `static/` were ported from `_reference/activity-log/web/{templates,static}` (the already-deployed, most mature UI in the whole app) as the shared baseline — every new module builds its pages on top of this instead of inventing its own look.

## Login flow

`login.html` is just credentials (staff picker is the default mode, not free-typed username) — on success it redirects to `/start`. `start.html` is the module picker (Medical Record, Inventory, Activity Log, and Settings for admins — `.module-picker`/`.module-card`, styled in `static/clearwave/app.css`). Every module page's `nav-logo` links back to `/start`, so a signed-in user can jump between modules anytime by clicking "medpost" — no re-authentication, no always-visible top-bar switcher (that got cramped once page-level nav links and module links shared one bar — see git history for the removed `module-nav.html` if resurrecting the idea). See `static/login.js` for the login form logic.

## Placeholder pages

`inventory.html` is a "still under development" stand-in — its module isn't built yet (see `../internal/README.md`), but the module picker already links to `/inventory`, so it exists to avoid a dead link/404 in the meantime. Replace with a real page during migration step 7.

## Medical Record page (`/emr`)

`emr.html` is the Medical Record module (called Electronic Medical Records until 2026-10-20; the URL stayed `/emr`). A sidebar offers Outpatient, Inpatient, Screening and Wellness. It looks like the Activity Log's: the `#mr-label` header and `#mr-nav` list share the `#health-programs-label` / `#program-list` rules in `clearwave/app.css`, and every section has a small triangle that expands and collapses it, and the sidebar title itself expands or collapses all of them. The heading on the right is two-coloured like the logo (`medicalRecordTitleParts` in `emr.js`). Screening opens to Drug and Alcohol, Fatigue and Malaria. The Drug and Alcohol table also has a **New drug & alcohol screening** button that switches the page to a web version of the offline consent and result form (`static/da-form-core.js`, `da-form-pdf.js`, `da-form.js`): sections A to D, every Name box a searchable list of patients, a signature that is a click showing the signer's first name in cursive (Dancing Script, `static/fonts`), **Save** (stores the record, clears the form) and **Save PDF** (the offline certificate layout, kept under 1 MB; jsPDF is `static/vendor/jspdf.min.js`, loaded on first use). The Fatigue table likewise has **New fatigue screening** (`static/fatigue-form-*.js`): the offline scoring sheet with live points and risk band, click-to-approve signatures for the worker and the examiner, **Save** and a one-page **Save PDF**. Drug and Alcohol and Fatigue each have two tabs, like Malaria, in one shared panel (`#mr-panel-screening`, `static/screening-log.js`). **Table** lists the uploaded records (alcohol: test date, name, company, position, test type, final result; fatigue: exam date, name, company, position, risk level, score total; clicking the first column opens every other column in a row below, bold red while open) with a name search, dd/mm/yyyy From/To boxes (filtering by the date the test was done, the alcohol test date read in clinic time, Asia/Jayapura) and **Export to Excel (.xlsx)** (all columns, same filters; with none, every record). **Dashboard** shows tiles and a stacked bar chart of outcomes per company, position or test type (alcohol: Negative, Positive, Sent to lab, Not stated) or per company, position or examiner (fatigue: Low, Mild, Medium, High, Not stated). They read `GET /api/screening-log`, `/api/screening-log.xlsx` and `/api/screening-log/summary` (`internal/screening/log_view.go`). The Activity Log's old per-program Test log tab is gone (removed 2026-10-21); a program's alcohol or fatigue activities link to these tables instead. Malaria has two tabs. **Table** lists the screenings (eight columns: Test ID, Date, Initial, Name, Position, Company, Test, Result; clicking a Test ID opens the rest of the record in a row below it, like the checkup table, and the ID turns bold red until it is closed) with a name search and an **Export to Excel (.xlsx)** button (all columns, same search; `GET /api/malaria-screenings.xlsx`), and a "New malaria exam" button that opens the entry form above the list (Cancel closes it and blanks it; saving keeps it open for the next patient). **Dashboard** shows how many screenings and patients, positives and pending results, and a bar chart by regency, district or village (positives in red), with a date filter; it reads `GET /api/malaria-screenings/summary` and reuses the MCU dashboard's bar styles. Every searchable box in the form (patient, regency, district, village) has a small x that clears it. The entry form is laid out like the medical checkup form (same `.add-activity` card, 4-column `.settings-grid`, dd/mm/yyyy date box, floating typeahead, read-only values as plain text; `static/date-dmy.js` holds the date-box code shared with `mcu.js`). `static/malaria.js`: searchable patient dropdown, week of the year, age/company/position shown read-only from the patient, weight max 150 kg, head of household cleaned as typed with "Sama dengan pasien", Regency, District and Village as searchable dropdowns (pick a regency first to limit the districts, or search any district directly with `?level=3&q=` and the regency fills itself; the village is searched within the chosen district), exam type, result, and the slide code to write on the blood slide, e.g. BSU1; saved through `/api/malaria-screenings`; helpers tested by `web/malaria.test.js`). Outpatient, Inpatient and Wellness show "Page still under development" and say "No sub-headers yet" when expanded. `static/emr.js` does the navigation; the URL hash is the only state (`#screening/fatigue`), so reload, back and a copied link all work. Its route helpers are tested by `web/emr-route.test.js` (`node --test web/*.test.js`) and the page content by `internal/activity-log/medical_record_page_test.go`.
