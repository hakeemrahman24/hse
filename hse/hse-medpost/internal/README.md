# internal

Go package layout — see `../plan/hse-medpost-plan.md` §1 for the reasoning (organize by feature/domain, not by type) and §2 for the full DDL. This file is the quick "who owns what table" index; the plan is the source of truth.

## Cross-domain packages (used by more than one module)

| Package | Owns | Used by |
|---|---|---|
| `patient/` | `Patient`, `NationalityTable` | `entrymcu`, `emr`, `screening`. **Built** — CRUD + `EnsureNationalitySeed` |
| `company/` | `EntityType`, `Company`, `CompanyRelation` | `patient`, `entrymcu`. **Built** — CRUD + `EnsureEntityTypeSeed`/`EnsureCompanySeed`/`EnsureCompanyRelationSeed` (real production roster: 54 companies, 48 relations, both LNG and GOKPL client projects), admin-editable via Settings |
| `staff/` | `MedpostStaffTable`, `AppUserTable`, `PositionRoleTable` — the whole app's staff roster + login/role system, despite the DDL being drafted inside `_reference/activity-log/plan/sql schema` | `emr`, `screening`, `activity-log`, login |
| `settings/` | `NotificationEmailTable` — whole-app setting owned by no single module. Admin-only CRUD; §3 of the plan is the requirements source | referenced nowhere yet (recipient list only, no send logic designed) |
| `auth/`, `config/`, `db/`, `middleware/` | app infrastructure, not domain data — lifted from `_reference/activity-log/internal/*` (generic parts only) | everything. **Built** — `cmd/server/main.go` runs against these today |
| `dates/`, `display/`, `storage/` | more app infrastructure | `dates`/`display`: activity-log. `storage/`: **Built** — file-upload path/filename conventions (`EvidenceDir`/`DocumentDir` for activity-log, `McuCertificateDir`/`McuCertificateFilename` for entrymcu's generated health certificates), used by both |
| `presence/` | No DB table — in-memory, poll-based "who's on this page right now" tracker (deliberately transient) | `entrymcu`'s `/mcu` page today (red "also on this page" banner), written generically enough to reuse for other pages later. **Built** |

## Per-module packages (owned by exactly one)

| Package | Owns | Status |
|---|---|---|
| `entrymcu/` | `McuRecord` (refactored: demographics moved to `patient/`, checkup-specific columns stay), `CheckUpCriteriaTable`, `TaskCategoryTable`, `McuCertificateLog` (certificate generate/download audit trail, `FK_PatientID` + `FK_McuRecordID`) | **Built end-to-end** — CRUD + `EnsureCheckUpCriteriaSeed`/`EnsureTaskCategorySeed`; `validity.go` ports legacy validity-date calc + renewal cascade; `certificate.go` generates + persists PDF health certificates to disk (pure-Go `fpdf`, no headless-Chrome/remote QR dependency), invalidating the cached copy whenever the record or the patient's cert-relevant fields are edited so a typo fix always regenerates fresh content; `report.go` backs the admin-only reporting/analytics grid + charts; `export.go` bulk-exports MCU data to one `.xlsx` with two sheets — **Patients** (one row per person: identity, blood type, NIK/passport) and **MCU entries** (one row per checkup, linked by `PatientID`; visit snapshot of company, position, and personal ID stays on the checkup row) — plus a zip of certificates (admin-only). Lookups and the certificate log are not their own sheets. A second download, `GET /api/mcu-records/mcu-data.xlsx` (any logged-in user), is one flat sheet: the checkup columns plus Gender, Nationality, BloodType, EmployeeID, and Parent / Project / Depth from `CompanyRelation` for that company (several relations stay on one checkup row, joined with ` / `). `dashboard_pdf.go` draws the admin summary: always the overall tables, table on the left and chart on the right, percentages on the chart, and a section that would cross the bottom margin moves to the next page. The page opens on Employee: one latest checkup per person (name, company, work position, latest medical ID, latest med status, medical validity). MCU data lists every visit. Either ID or name expands under the row (the checkup ID opens the full visit, the name opens the worker only); clicking the open link closes it. New patient opens the employee fields and a blank checkup together, with Cancel at the top and one Save that writes both. Smoking/vape is Yes or No. ECG and Treadmill are Normal, Acceptable - monitor, or Unacceptable. Incomplete locks result notes and requires a recommendation. `import.go` reads that workbook (and still accepts an older one-sheet checkup file): Patients sheet upserts identity, MCU sheet upserts by `CheckUpID`, per-row error reporting, no live-entry validation gate — a structural bulk load, not a simulated form submission; `emailnotify.go` + `McuEmailNotificationConfig` send an admin-configured (SMTP account, To/Cc, threshold days) near-expiry warning email on a schedule, excluding Close/Archived-Exit records, via a `RunEmailNotificationScheduler` goroutine started from `main.go`. Clinical entry form UI at `../web/templates/mcu.html` + `../web/static/mcu.js` is live (search + live name-typeahead-with-DOB, patient CRUD, checkup form with suggested-next-criteria, history, certificate download, admin reports/export panel, red "who else is on this page" presence banner). Deliberately not folded into `emr/` — a periodic MCU checkup and an ad-hoc EMR encounter are different record shapes even though both reference `Patient` |
| `activity-log/` | `HealthProcedureTable`, `ActivityTable`, `SupervisorTable`, `EvidenceTable`, `DocumentTable`, `SubHeaderTable`, `SubHeaderEntryTable`, `EntryEvidenceTable` | **Built** — programs, activities, evidence, documents, supervisors, sub-headers, bulk downloads. Activity summaries are plain text that may mix paragraphs with `- item` / `1. item` lines; the Activities feed renders those as lists. Package name is `activitylog` (Go identifiers can't have hyphens). Legacy source remains at `_reference/activity-log/` |
| `emr/` | `EmrTable`, `EmrMedicationTable` (dispense join — calls into `inventory/` to decrement stock) | **Started**: `Visit` + `MalariaScreening` (migrations `014_visit_malaria.sql` / mysql `022`), `malaria.go` (test ids like MAL-00042, create, list, set smear result, patient context, slide-initial preview), `malaria_summary.go` (dashboard counts and top regions, plus the shared date and name filters), `malaria_export.go` (Excel export with every column), `rules.go` (head-of-household cleaning, age, ISO week, slide code). Everything else in the EMR plan is not built. The Medical Record page `../web/templates/emr.html` (sidebar: Outpatient, Inpatient, Screening, Wellness) shows the alcohol and fatigue test logs and the malaria form; the other sections are placeholders |
| `region/` | `Region` (all 91,599 Indonesian areas; loaded by `../indonesia-region/load.sh`, not by the app) | `emr` malaria form. **Built** — `GET /api/regions?parent=CODE`, `?level=1..4`, or `?level=3&q=words&limit=` (search: every word must match the area's name or one of its three nearest parents; results carry `parentCode` and `path`) |
| `inventory/` | `MedicationTable` (master stock, split out of `emr/` since it grows independently — restocking, suppliers, expiry) | net-new, not yet built. Placeholder page at `../web/templates/inventory.html` |
| `screening/` | `DrugAlcoholScreening` (alcohol/drug test results), `FatigueScreening` (fatigue scoring results) | **Built** — offline forms upload records over the internet (`POST /api/screening/drug-alcohol`, `POST /api/screening/fatigue`, bearer token from `/api/screening/login`). The Medical Record page shows each as a Table and a Dashboard tab (`log_view.go`: `GET /api/screening-log`, `.xlsx`, `/summary`, filtered by test date and name). Staff can also type an alcohol record on that page: `POST /api/screening-log/alcohol` (`web_entry.go`, session login, stored once per record id). Fatigue likewise: `POST /api/screening-log/fatigue` (`web_fatigue.go`). MariaDB: `migrations/mysql/013_screening.sql` and `014_fatigue.sql` are run by hand. `VitalSignsCheckTable` is still not built |

## Naming note

There is deliberately no generic `internal/common` package — it would become a junk drawer. Shared data instead gets its own feature package (`patient`, `company`, `staff`), same as everything else.
